# Multi-agent work and independent review

The user explicitly requested multi-agent work. Four engineering agents worked concurrently with bounded ownership, shared evidence, and a coordinating agent responsible for integration. Their roles are separate from the ten simulated agent identities in the cache replay. The engineering agents audited and modified software; the simulated identities replay cached answers or symbolic attacks. This distinction avoids describing code-assistance activity as newly generated LLM swarm evidence.

The downloaded `source/` snapshot was kept separate from the editable `work/` copy. New results belong in the DGX verification paths; historical artifacts and manuscript numbers are not new measurements. No credential is included in the scientific evidence files.

## Verification responsibilities

The full-matrix comparator's focused suite checks recovery of a cyclic anti-expert when competent workers dominate, unseen tasks whose correct label is not currently reported, receiver-specific learned histories, neutral missing/unseen workers, metadata invariance, deterministic bounded fitting, and stable likelihoods. The research correction suite checks the native legacy symbolic sampler, closed/open candidate-pool semantics, and analytical coincidence expectations. New DGX protocol tests separately cover the scorer-valid MATH-500 pool and equivalent-answer scoring while retaining honest answer strings. The independent artifact checks in `docs/DGX_FINAL_REVIEW.md` additionally reconstruct primary and exact-string sensitivity scores from all saved traces. These are scientific software and artifact checks; they do not constitute measured benchmark superiority.

The cache auditor separately cross-checked error correlation against a reference implementation, checked receiver-conditioned coincidence against scalar calculations, checked missingness/conditioning identities, and verified artifact hashes. It did not perform model inference or reconstruct an absent historical content-hash chain.

The coordinator owns final integration testing, bounded smoke/standard execution, output completeness checks, and packaging verification. Test counts, final execution status, elapsed time, memory consumption, and measured outcomes should be read from the completed reports and manifests; this ledger does not predeclare successful simulations or copy historical result values.

Before publishing a scientific summary, check that it identifies the exact input cache, scorer, attack sampler, and executed slice; distinguishes new evidence from historical claims; reports inconclusive and adverse outcomes; and links each contribution to a corresponding artifact. Full Dawid–Skene has local-optimum and label-identifiability limits; cached replicas are dependent; historical calibration can overlap evaluation; the MATH-500 scorer is approximate; and bootstrap uncertainty alone cannot establish a general theoretical result.
